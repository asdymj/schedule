## 1. 테스트 전략

### 1.1 테스트 피라미드

| 레벨 | 도구 | 비중 (커버리지 목표) | 실행 시점 |
|------|------|---------------------|-----------|
| 단위 (Unit) | **Vitest** | 70% — 핵심 로직 80% (NFR-061) | 매 PR + watch |
| 통합 (Integration) | **Vitest + Supabase 로컬** | 20% — API 라우트 + DB | PR + nightly |
| E2E | **Playwright** | 10% — 8개 골든 패스 | PR + main 머지 |
| 접근성 | **axe-core + Playwright** | 모든 페이지 자동 검사 | PR (NFR-031) |
| 성능 | **Lighthouse CI + k6** | 핵심 페이지 + 부하 (NFR-001~005, NFR-050) | nightly |
| 보안 | **OWASP ZAP + Snyk** | OWASP Top 10 (NFR-027) | weekly + 배포 직전 |
| 회귀 | **Visual Regression — Chromatic 또는 Playwright snapshot** | 핵심 컴포넌트 | PR (옵션) |

### 1.2 환경

| 환경 | 용도 | DB |
|------|------|----|
| local | 개발자 단위 | Supabase 로컬 (`supabase start`) |
| ci-integration | GitHub Actions Vitest | 로컬 Postgres + 시드 |
| preview | Vercel PR Preview | Supabase Staging (격리 schema) |
| staging | E2E + 부하 | Supabase Staging |
| production | 모니터링 + Smoke | Supabase Prod |

### 1.3 TC ID 체계

`TC-<영역>-<번호>` (3자리). 영역: AUTH / GROUP / EVENT / EDITOR / SOCIAL / NOTIFY / ARCHIVE / PWA / SEC / PERF / A11Y / PAY.

### 1.4 우선순위 정의

| 등급 | 의미 |
|------|------|
| **P0** | MVP 런칭 차단(blocker) — 실패 시 No-Go |
| **P1** | 정식 런칭 차단 |
| **P2** | 확장 단계 |
