# 디자인 스타일 가이드 (Design Style Guide)

**프로젝트명**: 모먼토(Momento) — 온라인 다이어리 꾸미기 (Shared Diary Calendar)
**작성일**: 2026-06-07
**버전**: v1.0
**관련 산출물**: [서비스기획서](../02.기획문서/서비스기획서.md), [화면설계서](../02.기획문서/화면설계서.md), [정보구조도](../02.기획문서/정보구조도.md)
**기술 스택**: Next.js 14 (App Router) + Tailwind CSS / Pretendard·Inter / 모바일 퍼스트 PWA

> 본 문서는 프론트엔드 구현의 시각적 단일 기준입니다. 화면설계서 §1.1에서 사전 확정한 디자인 토큰을 정본화하고, 서비스기획서 §5의 브랜드 전략을 시각 언어로 확장합니다. Figma 디자인 및 W4 프론트엔드 코드 생성 시 본 문서를 참조합니다.

## 1. 디자인 원칙

모먼토는 "우리만 보는 캘린더에, 우리만의 추억을 토핑한다"는 가치 제안(서비스기획서 §4.1)을 시각적으로 구현합니다. 모든 디자인 결정은 아래 5대 원칙을 따릅니다.

1. **감성 우선 (Warm & Playful)**: 차가운 생산성 도구가 아니라, 친구가 옆에서 다꾸를 같이 해주는 따뜻한 경험. 코랄 핑크 기반의 부드러운 색채와 둥근 모서리, 손글씨 액센트로 정서적 친밀감을 전달합니다.
2. **모바일 퍼스트 (Mobile First)**: 320px 기준으로 먼저 설계하고 데스크탑으로 확장합니다. 터치 타겟 44px 이상, 엄지 도달 영역(Bottom Tab/FAB) 우선 배치.
3. **꾸미기를 위한 절제된 캔버스 (Quiet Canvas)**: UI 크롬(헤더·내비·도구)은 의도적으로 차분하게 두어, 사용자가 채우는 사진·스티커·지도가 주인공이 되게 합니다. 시스템 UI는 배경, 사용자 콘텐츠는 전경.
4. **폐쇄형 안전감 (Intimate & Safe)**: 우리 그룹만의 공간임을 색상 링(그룹 색상)과 멤버 아바타로 일관되게 시각화하여, 닫힌 무대의 심리적 안정감을 제공합니다.
5. **접근성·일관성 (Accessible & Consistent)**: 색상만으로 의미를 전달하지 않고(아이콘+텍스트 병행), WCAG 2.1 AA 대비율을 준수하며, 라이트/다크 모드 전 구간에서 동일한 경험을 보장합니다.

## 2. 글로벌 레이아웃

모먼토는 대시보드형이 아닌 **콘텐츠 소비/창작형** 서비스로, 플랫폼별로 내비게이션 패러다임이 다릅니다.

### 2.1 레이아웃 구조 (플랫폼별)

**모바일 (기본, 320~767px)** — Bottom Tab 중심

```
+-----------------------------------+
|          Top Bar (56px)           |  그룹 스위처 / 검색 / 알림
+-----------------------------------+
|                                   |
|                                   |
|          Main Content             |  스크롤 영역 (fluid)
|          (1 컬럼)                  |
|                                   |
|                                   |
+-----------------------------------+
|    Bottom Tab + FAB (56px)        |  캘린더 / 피드 / + / 갤러리 / 마이
+-----------------------------------+
```

**데스크탑 (1024px 이상)** — 사이드바 중심

```
+--------+--------------------------------------+
|        |          Top Bar (64px)              |
| Side   +--------------------------------------+
| bar    |                                      |
| (240px)|          Main Content                |
| 그룹   |          (max 1080px, 중앙 정렬)      |
| 카드   |                                      |
| /마이  |          (캔버스/지도는 풀 폭)        |
| /알림  |                                      |
+--------+--------------------------------------+
```

| 영역 | 모바일 | 데스크탑 | 배경색 | 비고 |
|------|--------|----------|--------|------|
| Top Bar | H: 56px, 전체 너비 | H: 64px | `--color-surface` | 그룹 스위처, 검색, 알림 배지 |
| Bottom Tab | H: 56px + Safe Area | 미사용 | `--color-surface` | 5개 탭 + 중앙 FAB |
| 사이드바 | 미사용(드로어로 대체) | W: 240px | `--color-bg` | 그룹 카드 리스트, 마이/알림/설정 |
| 메인 콘텐츠 | 1 컬럼, 16px 패딩 | Max-W: 1080px, 32px 패딩 | `--color-bg` | 캔버스·지도는 풀 폭 예외 |
| 우측 패널(Wide ≥1440) | — | W: 280px | `--color-bg` | 에디터 도구, 활동 피드 |

> 캘린더 월 뷰, 캔버스 에디터, 추억 지도는 콘텐츠 특성상 max-width 제약 없이 가용 영역을 모두 사용합니다.

### 2.2 그리드 시스템

| 항목 | 모바일 | 데스크탑 |
|------|--------|----------|
| 컬럼 수 | 4 | 12 |
| 거터(간격) | 16px | 24px |
| 외곽 마진 | 16px | 32px |
| 콘텐츠 최대 너비 | 100% | 1080px (지도/캔버스는 예외) |
| 캘린더 셀 | 7열 균등 분할 (요일) | 7열 균등 분할 |
| 갤러리 그리드 | 3열 정사각 | 6열 정사각 |

### 2.3 스페이싱 스케일 (4pt grid)

화면설계서 §1.1의 `4·8·12·16·24·32·48·64` 스케일을 정본으로 합니다.

| 토큰 | 값 | 용도 |
|------|-----|------|
| space-1 | 4px | 아이콘-텍스트 간격, 인접 인라인 요소 |
| space-2 | 8px | 칩 내부 패딩, 밀집 요소 간격 |
| space-3 | 12px | 리스트 항목 간격, 입력 필드 내부 |
| space-4 | 16px | 카드 내부 패딩, 모바일 외곽 마진 |
| space-5 | 24px | 섹션 간 간격, 카드 간 간격 |
| space-6 | 32px | 데스크탑 콘텐츠 패딩, 대형 섹션 |
| space-7 | 48px | 페이지 블록 구분, 빈 상태 여백 |
| space-8 | 64px | 페이지 상하 여백, 히어로 영역 |

색상은 항상 아이콘·텍스트와 함께 사용합니다(색상 단독 금지, 원칙 5).

| 상태 | 토큰 | 텍스트/아이콘 | 배경 (라이트) | 용도 |
|------|------|---------------|---------------|------|

### 3.6 표면 계층 (Elevation)

| 레벨 | 배경 | 그림자/보더 | 용도 |
|------|------|-------------|------|

## 5. 아이콘

### 5.1 아이콘 스타일

| 항목 | 값 |
|------|-----|
| 라이브러리 | **Lucide React** (Next.js 호환, 트리셰이킹) |
| 스타일 | Outlined stroke (filled 아님) |
| Stroke 너비 | 1.75px (기본), 2px (20px 미만) |
| 색상 | 기본 `--color-text-secondary`, 활성 `--color-primary` |

> 감성 표현(리액션, 스티커, 그룹 아이콘)은 Lucide가 아닌 **이모지/일러스트 에셋**을 사용합니다. Lucide는 기능 아이콘(내비, 액션)에 한정합니다.

## 6. 핵심 UI 컴포넌트

### 6.1 버튼 (Button)

| Variant | 배경 | 텍스트 | 보더 | 용도 |

| 패딩 | 좌우 20px |
| 텍스트 | Body Strong |

## 8. 인터랙션 & 모션

### 8.1 트랜지션 원칙

| 항목 | 값 |
|------|-----|
| Timing function | ease-out (진입), ease-in (이탈) |
| Micro | 100ms (탭 피드백, 토글) |
| Fast | 200ms (호버, 탭 전환) |
| Normal | 300ms (모달, 페이지 전환, 토스트) |
| Slow | 500ms (온보딩 단계, 큐레이션 슬라이더) |

### 8.2 주요 인터랙션

| 요소 | 트리거 | 효과 | 시간 |
|------|--------|------|------|
| 페이지 전환 (캘린더 월) | 스와이프/네비 | Slide left/right | 300ms |
| 모달/바텀시트 | open | fade + slide-up + scale | 300ms |
| 카드 호버 (데스크탑) | hover | translateY(-2px) + 그림자 | 200ms |
| 버튼 클릭 | active | scale(0.98) + Haptic(모바일) | 100ms |
| 리액션 추가 | tap | 이모지 pop scale(1→1.3→1) + 카운트 증가 (Optimistic) | 200ms |
| 토스트 | trigger | 슬라이드 인/아웃 | 300ms |
| 탭 전환 | tap | 인디케이터 슬라이드 | 200ms |
| Pull to refresh | drag-down | 스피너 + 콘텐츠 리로드 | — |
| 캘린더 일정 점 → 셀 상세 | tap | 펼침 expand | 200ms |
| 알림 카드 스와이프 | swipe | 좌(읽음)/우(삭제) 슬라이드 | 200ms |

### 8.3 Optimistic UI & Haptic

- **Optimistic UI**: 댓글 작성, 리액션, 일정 생성은 서버 응답 전 즉시 반영 후 실패 시 롤백 + 토스트.
- **Haptic**: 리액션, 삭제 확인, 길게 누르기 메뉴 진입 시 가벼운 진동(모바일).

## 9. 반응형 & 접근성

### 9.1 브레이크포인트 (화면설계서 §1.4 정합)

| 이름 | 너비 | 레이아웃 |
|------|------|----------|
| Mobile (기본) | 320 ~ 767px | 1 컬럼, Bottom Tab + FAB |
| Tablet | 768 ~ 1023px | 2 컬럼 가능, Top Nav |
| Desktop | 1024 ~ 1439px | 사이드바(240px) + 메인 |
| Wide | ≥ 1440px | 사이드바 + 메인 + 우측 패널(280px) |

> Tailwind 설정: `sm:768`, `md:1024`, `lg:1440`. 기본(모바일) 우선 작성, 상위 브레이크포인트는 `md:`/`lg:` 프리픽스로 확장.

### 9.2 접근성 (WCAG 2.1 AA, NFR-031)

| 항목 | 기준 |
|------|------|
| 터치 타겟 | 최소 44×44px (모든 버튼/아이콘, REQ-063) |
| 텍스트 대비율 | 본문 최소 4.5:1, 큰 텍스트 3:1 (axe 검사) |
| 포커스 인디케이터 | 2px outline, Primary, 2px offset (모든 인터랙티브 요소) |
| 상태 표시 | 색상 + 아이콘 병행 (색상 단독 금지) |
| 에러 표시 | 아이콘 + 텍스트 + 보더 (3중 코딩) |
| ARIA | 아이콘 버튼 `aria-label`, 이미지 `alt`, 토스트 `aria-live` |
| 키보드 | Tab 순서, ESC로 모달 닫기, Enter로 제출 |
| 모션 | `prefers-reduced-motion` 존중 (전환 최소화) |
| 다크모드 | 라이트/다크 전 토큰 정의, 시스템 자동 전환 지원 |

> 코랄 핑크(`#FF8FA3`) 위 흰 텍스트는 대비율 미달이므로, Primary 버튼 텍스트는 흰색을 쓰되 굵기 600 이상 + 충분한 크기로 가독성 보강. 작은 텍스트에 Primary를 본문색으로 쓰지 않고 `--color-primary-dark`를 사용합니다.

## 10. 디자인 토큰 네이밍 규칙

Tailwind `theme.extend` 및 CSS Custom Properties로 구현합니다. 라이트/다크는 `:root` / `[data-theme="dark"]` 또는 `prefers-color-scheme`로 분기합니다.

```
/* 컬러: color/{역할}/{변형} */
--color-primary
--color-primary-dark
--color-primary-light
--color-secondary
--color-accent
--color-bg
--color-surface
--color-surface-sunken
--color-text-primary
--color-text-secondary
--color-text-tertiary
--color-border
--color-success / --color-warning / --color-danger / --color-info

/* 그룹 색상: color/group/{n} */
--color-group-1 ... --color-group-8

/* 타이포: 토큰명 → Tailwind 클래스 */
text-display / text-h1 / text-h2 / text-h3
text-body / text-body-strong / text-body-sm
text-caption / text-overline

/* 스페이싱 (4pt): space-1 ~ space-8 → Tailwind p-/m-/gap- */
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64

/* 반경: radius/{크기} */
radius-card     = 8px
radius-button   = 12px
radius-modal    = 16px
radius-pill     = 9999px

/* 그림자: shadow/{레벨} */
shadow-card     = 0 2px 8px rgba(0,0,0,0.06)
shadow-modal    = 0 12px 32px rgba(0,0,0,0.16)

/* 모션: motion/{속도} */
motion-micro    = 100ms
motion-fast     = 200ms
motion-normal   = 300ms
motion-slow     = 500ms
```

### 10.1 Tailwind 적용 예시

```js
// tailwind.config.js (theme.extend)
colors: {
  primary: { DEFAULT: '#FF8FA3', dark: '#E57389', light: '#FFE3E9' },
  secondary: '#B5A3FF',
  accent: '#FFD66B',
  // ... CSS 변수 참조 권장: 'var(--color-bg)' 형태로 다크모드 자동 전환
},
borderRadius: { card: '8px', button: '12px', modal: '16px' },
boxShadow: {
  card: '0 2px 8px rgba(0,0,0,0.06)',
  modal: '0 12px 32px rgba(0,0,0,0.16)',
},
```
