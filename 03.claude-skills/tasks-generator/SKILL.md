# 태스크 정밀 생성기

기획서/PRD를 분석하여 개발팀이 바로 착수할 수 있는 구체적인 태스크 목록을 생성합니다.

## 분석 프로세스

### Step 1: 기획서 분석
- 핵심 기능 추출
- 사용자 스토리 식별
- 기술적 요구사항 파악
- 의존성 관계 매핑

### Step 2: 태스크 분해 원칙

**INVEST 원칙 적용:**
- **I**ndependent: 독립적으로 개발 가능
- **N**egotiable: 협의 가능한 범위
- **V**aluable: 사용자 가치 제공
- **E**stimable: 추정 가능한 크기
- **S**mall: 1-3일 내 완료 가능
- **T**estable: 테스트 가능

### Step 3: 태스크 카테고리

```
📁 Backend
  ├── API 설계/구현
  ├── 데이터베이스 모델링
  ├── 비즈니스 로직
  └── 인증/보안

📁 Frontend
  ├── UI 컴포넌트
  ├── 페이지/라우팅
  ├── 상태 관리
  └── API 연동

📁 Infrastructure
  ├── 환경 설정
  ├── CI/CD
  ├── 모니터링
  └── 배포

📁 Quality
  ├── 단위 테스트
  ├── 통합 테스트
  ├── E2E 테스트
  └── 문서화
```

## 태스크 출력 형식

각 태스크는 다음 형식으로 작성:

```markdown
### [카테고리] 태스크 제목

**설명:**
구체적인 작업 내용

**수용 기준 (Acceptance Criteria):**
- [ ] 조건 1
- [ ] 조건 2
- [ ] 조건 3

**기술 노트:**
- 사용할 기술/라이브러리
- 참고할 기존 코드
- 주의사항

**의존성:** 선행 태스크 ID
**예상 소요:** S(0.5일) / M(1일) / L(2일) / XL(3일+)
**우선순위:** P0(필수) / P1(중요) / P2(선택)
```

## 추가 산출물

### 1. 의존성 다이어그램
```
[인증 API] ──→ [사용자 관리 UI] ──→ [대시보드]
     │
     └──→ [권한 관리] ──→ [관리자 페이지]
```

### 2. 스프린트 제안
```
Sprint 1 (MVP Core)
├── Task 1, 2, 3...

Sprint 2 (Feature Complete)
├── Task 4, 5, 6...

Sprint 3 (Polish & Launch)
├── Task 7, 8, 9...
```

### 3. 리스크 태스크
- 기술적 불확실성이 높은 항목
- 외부 의존성이 있는 항목
- 스파이크/PoC가 필요한 항목

## 실행

기획서 입력: $ARGUMENTS

1. 위 기획서를 분석하세요
2. INVEST 원칙에 따라 태스크를 분해하세요
3. 의존성을 고려한 실행 순서를 제안하세요
4. 선택적으로 TaskCreate 도구를 사용하여 태스크를 생성하세요
