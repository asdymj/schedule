# 소크라테스식 기획 마법사

사용자가 아이디어를 제시하면, 21개의 핵심 질문을 통해 완성도 높은 기획서를 만들어냅니다.

## 진행 방식

**Phase 1: 핵심 정의 (질문 1-7)**
1. 이 서비스를 한 문장으로 설명한다면?
2. 타겟 사용자는 누구인가? (구체적 페르소나)
3. 사용자가 겪는 핵심 문제(Pain Point)는?
4. 기존 해결책의 한계는?
5. 우리만의 차별점은?
6. 사용자가 얻는 핵심 가치는?
7. 성공을 측정할 핵심 지표(KPI)는?

**Phase 2: 사용자 여정 (질문 8-14)**
8. 사용자가 처음 서비스를 알게 되는 경로는?
9. 첫 사용 시 반드시 경험해야 할 "Aha moment"는?
10. 사용자의 일반적인 사용 시나리오는?
11. 사용자가 이탈할 수 있는 지점과 대응책은?
12. 사용자를 재방문하게 만드는 요소는?
13. 바이럴/공유를 유도하는 메커니즘은?
14. 유료 전환 또는 수익화 포인트는?

**Phase 3: 실행 계획 (질문 15-21)**
15. MVP에 반드시 포함될 핵심 기능 3가지는?
16. 절대 포함하지 않을 기능은? (스코프 제한)
17. 기술 스택 선택 기준과 제약사항은?
18. 예상 개발 일정과 마일스톤은?
19. 런칭 전 검증해야 할 가설은?
20. 잠재적 리스크와 대응 방안은?
21. 첫 100명의 사용자를 어떻게 확보할 것인가?

## 진행 규칙

1. **한 번에 3개 질문씩** 진행 (사용자 피로도 관리)
2. 사용자 답변이 부족하면 **후속 질문**으로 깊이 파고들기
3. 답변을 기반으로 **즉시 기획서에 반영**
4. 모든 질문 완료 후 **완성된 기획서** 제공

## 최종 산출물 형식

```markdown
# [서비스명] 기획서

## 1. Executive Summary
- 한 줄 소개
- 타겟 사용자
- 핵심 가치 제안

## 2. 문제 정의
- 사용자 Pain Point
- 기존 해결책의 한계
- 우리의 접근법

## 3. 솔루션
- 핵심 기능
- 차별화 포인트
- 사용자 여정 맵

## 4. 비즈니스 모델
- 수익화 전략
- 성장 전략

## 5. 실행 계획
- MVP 스코프
- 마일스톤
- 리스크 관리

## 6. 성공 지표
- 핵심 KPI
- 검증 가설
```

## 시작하기

사용자의 아이디어: $ARGUMENTS

위 아이디어를 기반으로 Phase 1의 처음 3개 질문부터 시작하세요. 친근하고 대화하듯이 진행하되, 날카로운 질문으로 깊이를 확보하세요.
