## 1. 개요

### 1.1 문서 목적

본 문서는 서비스기획서(#4)에서 정의한 서비스 범위(§4.2)를 시스템 기능 단위로 분해하여, 개발자가 구현 가능한 수준으로 상세화합니다. 각 기능은 입력/처리/출력, 사전·사후 조건, 예외 처리를 포함합니다.

### 1.2 기능 ID 체계

| 모듈 | ID 범위 | 영역 | 레이어 (서비스기획서 §4.3 정합) |
|------|---------|------|---------------------------------|
| 회원/인증 | F-001 ~ F-099 | 소셜 로그인, 세션, 프로필 | Base |
| 그룹 관리 | F-100 ~ F-199 | 그룹 생성, 초대, 멤버 권한 | Base |
| 캘린더/일정 | F-200 ~ F-299 | 일정 CRUD, 다중 뷰, 필터 | Base Layer (일정의 뼈대) |
| 꾸미기 에디터 | F-300 ~ F-399 | 캔버스, 지도/사진/영상/스티커 | Middle Layer (추억 매핑) |
| 리액션/댓글 | F-400 ~ F-499 | 이모지 리액션, 댓글, 멘션 | Top Layer (감성 토핑) |
| 알림 | F-500 ~ F-599 | 웹 푸시, 이메일, D-day | Cross-cutting |

| 시스템/설정 | F-700 ~ F-799 | 다크모드, PWA, 환경설정 | Cross-cutting |

### 1.3 우선순위 정의 (MoSCoW)

| 등급 | 의미 | 적용 시점 |
|------|------|-----------|
| **P0 (Must)** | MVP 필수 — 미구현 시 서비스 가치 미달 | W4~W12 (Phase 1 MVP) |
| **P1 (Should)** | 정식 런칭 시 필수 — 차별화 강화 | W13~W16 (Phase 2 안정화) |
| **P2 (Could)** | 확장/고도화 — 검증 후 추가 | M3+ (Phase 2/3 확장) |
| **W (Won't)** | MVP 범위 외 | Phase 3+ 또는 영구 제외 |

### 1.4 표 표기 규칙

- **입력**: 사용자 입력 또는 시스템 입력 데이터
- **처리**: 핵심 비즈니스 로직 (1~5단계 흐름)
- **출력**: 화면/응답/저장된 데이터
- **사전조건**: 기능 실행 전 충족되어야 할 조건
- **예외**: 실패 시 처리 방식 및 사용자 피드백

## 3. 회원/인증 모듈 (F-001 ~ F-099)

### F-001 소셜 로그인 (Kakao / Google / Apple)

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-001 (소셜 로그인 Must) |
| 설명 | 소셜 OAuth 2.0 기반 로그인. Z세대 가입 마찰 최소화를 위해 이메일/비밀번호 회원가입은 제공하지 않음 |
| 입력 | OAuth Provider 선택 (Kakao / Google / Apple), Provider 인증 토큰 |
| 처리 | 1) Supabase Auth가 OAuth Provider 리다이렉트 처리 → 2) 콜백 시 토큰 검증 → 3) 신규 사용자면 `profiles` 테이블에 기본 프로필 자동 생성 → 4) JWT 세션 발급 |
| 출력 | 로그인 성공 → 홈(`/home`) 리다이렉트, 신규 가입 시 온보딩 화면(`/onboarding`) |
| 사전조건 | Supabase Auth Provider 등록 완료 (Kakao/Google/Apple OAuth 키 발급) |
| 예외 | Provider 인증 실패 → 토스트 알림 "로그인에 실패했습니다. 다시 시도해주세요" + 로그인 화면 유지 |

### F-002 자동 로그인 / 다중 디바이스 세션

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-004 (다중 디바이스 동시 로그인 Must) |
| 설명 | JWT Refresh Token 기반 자동 로그인 + 최대 5개 디바이스 동시 세션 관리 |
| 입력 | 브라우저 저장소(localStorage)의 Refresh Token, 디바이스 핑거프린트 |
| 처리 | 1) 앱 진입 시 Refresh Token 존재 확인 → 2) Supabase Auth `refreshSession()` 호출 → 3) `user_sessions` 테이블에 디바이스별 세션 기록 → 4) 6번째 디바이스 로그인 시 가장 오래된 세션 자동 종료 |
| 출력 | 자동 로그인 성공 → 홈 / 실패 → 로그인 화면 / 설정에서 디바이스 목록 조회·원격 로그아웃 |
| 사전조건 | 이전 로그인 이력 존재 |
| 예외 | Refresh Token 만료(30일) → 로그인 화면으로 이동, 토큰 정리 |

### F-003 로그아웃

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-004 (다중 디바이스 세션 관리 일부) |
| 설명 | 현재 세션 종료 및 토큰 정리 |
| 입력 | 사용자 액션 (마이페이지 > 로그아웃 버튼) |
| 처리 | 1) 확인 다이얼로그 → 2) Supabase `signOut()` 호출 → 3) localStorage 토큰 제거 → 4) 모든 그룹 채널 구독 해제 |
| 출력 | 로그인 화면으로 이동 |
| 사전조건 | 로그인 상태 |
| 예외 | 네트워크 실패 시에도 로컬 토큰은 즉시 제거 (재로그인 강제) |

### F-004 프로필 수정 (닉네임, 프로필 사진, 자기소개)

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-002 (닉네임/프로필/자기소개 Must) |
| 설명 | 그룹원에게 표시될 본인 정보 편집 |
| 입력 | 닉네임 (2~20자), 프로필 사진 (선택, 최대 5MB), 자기소개 (선택, 최대 100자) |
| 처리 | 1) 닉네임 중복 체크는 하지 않음 (동명 허용) → 2) 프로필 사진 업로드 시 정사각 크롭 + 200x200 리사이즈 → 3) `profiles` 테이블 업데이트 |
| 출력 | 마이페이지에 즉시 반영, 그룹원 멤버 리스트 실시간 갱신 (Supabase Realtime) |
| 사전조건 | 로그인 상태 |
| 예외 | 닉네임 길이 초과 → 인라인 에러 "닉네임은 2~20자입니다" / 사진 용량 초과 → "5MB 이하 이미지만 가능합니다" |

### F-005 회원 탈퇴

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** (요구사항정의서 정합 — REQ-003 Must) |
| 관련 REQ | REQ-003 (탈퇴 시 일괄 삭제·익명화 Must), NFR-026 (감사 로그) |
| 설명 | 계정 영구 삭제. 본인이 작성한 데이터는 익명화 처리 (그룹원의 추억 보존) |
| 입력 | 본인 OAuth 재인증 + 탈퇴 사유 (선택) |
| 처리 | 1) OAuth 재인증 → 2) 본인 작성 일정·댓글·리액션의 `user_id`를 NULL로 변경, 닉네임을 "(탈퇴 사용자)"로 표시 → 3) 24시간 내 `profiles` 영구 삭제 → 4) 미디어 30일 유예 후 삭제, 감사 로그 1년 보존 |
| 출력 | 탈퇴 완료 토스트 → 로그인 화면 이동 |
| 사전조건 | 로그인 상태, 본인 운영 그룹의 다른 운영자 위임 완료 (운영자 단독 그룹은 그룹 해체 안내) |
| 예외 | 본인이 단독 운영자인 그룹 존재 → "그룹을 먼저 해체하거나 운영 권한을 위임해주세요" |

### F-006 차단/신고 (P2)

| 항목 | 내용 |
|------|------|
| 우선순위 | **P2** |
| 관련 REQ | REQ-089 (백오피스 신고 처리 Could) |
| 설명 | 부적절한 콘텐츠/사용자 신고. 폐쇄형 서비스 특성상 우선순위 낮음 |

| 출력 | "신고가 접수되었습니다" 토스트 |
| 사전조건 | 로그인 상태 |

## 4. 그룹 관리 모듈 (F-100 ~ F-199)

### F-101 그룹 생성

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-010 (그룹 생성·테마 컬러 Must), REQ-013 (멤버 한도 Must) |
| 설명 | 새 폐쇄형 그룹 생성. 생성자는 자동으로 운영자(owner) 권한 부여 |
| 입력 | 그룹명 (1~30자), 그룹 색상 (8종 프리셋, 색맹 친화 팔레트), 그룹 아이콘 (이모지 1개), 그룹 유형 (친구/커플/가족/동호회) |
| 처리 | 1) `groups` 테이블 INSERT → 2) `group_members` 테이블에 생성자를 owner role로 INSERT → 3) RLS 정책 자동 적용 (생성자만 즉시 접근) |
| 출력 | 그룹 생성 완료 → 해당 그룹의 캘린더 화면(`/g/[group_id]`) 진입 |
| 사전조건 | 로그인 상태, Free 플랜의 경우 본인 운영 그룹 5개 미만 (Pro는 무제한, 서비스기획서 §6.2 정합) |
| 예외 | 그룹 수 한도 초과 → "Free 플랜은 그룹 5개까지 운영 가능합니다. Pro로 업그레이드하세요" / 그룹원 5인 초과 시 Pro 안내 모달 |

### F-102 그룹 초대 링크 / 코드 발급

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-011 (일회성 초대 링크·6자리 코드 Must), NFR-023 (1회 사용 또는 24시간 만료) |
| 설명 | 일회성 초대 링크 또는 6자리 코드 발급. 24시간 만료 또는 1회 사용 시 만료 (NLM PDF p.13 Risk 3 대응) |
| 입력 | 그룹 ID, 만료 옵션 (기본: 1회 사용 또는 24시간) |
| 처리 | 1) 256bit 랜덤 토큰 생성 → 2) `group_invites` 테이블에 만료일시·사용 여부 저장 → 3) 초대 URL(`https://[domain]/invite/[token]`) + 6자리 단축 코드 발급 |
| 출력 | 공유 가능한 링크 + 6자리 코드, 카카오톡/시스템 공유 시트 호출 |
| 사전조건 | 로그인 상태, 해당 그룹의 owner 또는 admin 권한 |
| 예외 | 권한 없음 → "초대 링크는 운영자만 발급할 수 있습니다" / 코드 재발급은 무제한 허용 |

### F-103 그룹 초대 수락 (링크/코드 가입)

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-012 (초대 링크/코드 참여 Must), NFR-021 (RLS) |
| 설명 | 초대 링크 클릭 또는 코드 입력으로 그룹 가입 |
| 입력 | 초대 토큰 또는 6자리 코드 |
| 처리 | 1) 토큰 유효성 검증 (만료/사용 횟수) → 2) 본인 가입 여부 확인 (중복 차단) → 3) `group_members`에 member role로 INSERT → 4) 잔여 횟수 -1 → 5) 그룹원 전체에 "OO님이 합류했어요" 알림 |
| 출력 | 그룹 캘린더 화면 진입 + 환영 토스트 |
| 사전조건 | 로그인 상태 (비로그인 시 로그인 화면 후 자동 복귀) |
| 예외 | 만료 → "초대 링크가 만료되었습니다. 운영자에게 새 링크를 요청해주세요" / 이미 가입 → "이미 가입된 그룹입니다" |

### F-104 그룹 멤버 목록 조회 / 그룹 스위처

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-016 (그룹 목록·빠른 전환 Must, 응답 1초 이내), NFR-021 (RLS) |
| 설명 | 그룹원 닉네임·프로필 사진·권한·가입일 표시 + 좌측 사이드바(데스크탑) / 하단 드로어(모바일) 그룹 스위처 |
| 입력 | 그룹 ID |
| 처리 | 1) `group_members` JOIN `profiles` 조회 → 2) RLS로 본인 소속 그룹만 조회 가능 |
| 출력 | 멤버 리스트 (운영자 우선 정렬, 가입일 순) |
| 사전조건 | 해당 그룹의 멤버 |
| 예외 | RLS 위반 (외부 접근 시도) → 403 Forbidden |

### F-105 그룹 멤버 권한 변경 / 그룹장 이양

| 항목 | 내용 |
|------|------|
| 우선순위 | **P0** |
| 관련 REQ | REQ-014 (강퇴·권한 이양 Must) |

| 처리 | 1) Service Worker로 GET 응답 캐시 → 2) POST/PUT은 IndexedDB 큐 적재 → 3) 온라인 복귀 시 자동 sync |
| 출력 | 상단 "오프라인 모드" 배너 |
| 사전조건 | F-701 |
| 예외 | 큐 충돌 → Last-Write-Wins + 사용자 알림 |

### F-704 다국어 (i18n, P1)

| 항목 | 내용 |
|------|------|
| 우선순위 | **P1** |
| 설명 | 한국어/영어 우선, 이후 일본어 확장 (글로벌 시장 30% 목표 — 서비스기획서 §9.1 Scale 단계) |

| 처리 | next-i18next 적용 |
| 출력 | 모든 UI 텍스트 번역 |
| 사전조건 | 번역 키 정리 |
| 예외 | 키 누락 → 한국어 폴백 |

### F-705 결제 / 구독 관리 (Pro 업그레이드, P2)

| 항목 | 내용 |
